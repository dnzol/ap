# AP Mapper

Android-приложение для сбора базы Wi‑Fi точек доступа и BLE-маяков с привязкой к GPS.
Записывает сырые наблюдения (точка + уровень сигнала + где вы стояли) и экспортирует их в CSV формата WiGLE (WigleWifi-1.4).

## Сборка

Нужен Android Studio (Ladybug или новее) и JDK 17.

1. File → Open → выберите папку `ApMapper`. Студия сама скачает Gradle и Android SDK 35 (согласитесь на установку, если предложит).
2. Включите на телефоне «Отладку по USB», подключите, нажмите Run ▶.
3. Или из консоли (когда студия создала wrapper): `./gradlew assembleDebug` → `app/build/outputs/apk/debug/app-debug.apk`.

Проект не использует androidx и сторонние библиотеки: minSdk 26 (Android 8.0), Kotlin, только системные API.

> Проект написан без компиляции в тестовой среде. Если студия покажет ошибку сборки, пришлите текст ошибки, и я поправлю.

## Как пользоваться

1. Запустите приложение, нажмите «Старт», дайте разрешения (точная геолокация, Bluetooth-сканирование, уведомления).
2. Включите GPS в системе. Дождитесь статуса «Идёт запись · GPS ±N м».
3. Ходите/ездите. Запись идёт в фоне (foreground-сервис с уведомлением), экран можно выключить.
4. «Экспорт в CSV» → выберите, куда сохранить. Файл можно загрузить на wigle.net или обработать своим скриптом.
5. Или отправьте данные на свой сервер (папка `server/`, инструкция в `server/README.md`): в блоке «Сервер» введите `https://...` и токен, нажмите «Отправить на сервер». Каждый раз уходит только то, что ещё не отправлялось; повторная отправка безопасна, дубликаты сервер отбрасывает.

## Что записывается

- **Wi‑Fi:** BSSID, SSID, тип защиты, частота (канал), RSSI, координаты, погрешность GPS, высота, время (UTC).
- **BLE:** по умолчанию только маяки iBeacon (uuid:major:minor) и Eddystone-UID, их стабильный id попадает в колонку SSID. Режим «все устройства» выключен по умолчанию.

Что отбрасывается:
- наблюдения без свежей GPS-координаты или с погрешностью хуже заданного порога (по умолчанию 30 м);
- устаревшие кэшированные результаты Wi‑Fi-скана;
- сети, чей SSID оканчивается на `_nomap` (владелец просит не вносить в карты);
- в режиме «все BLE»: адреса с битом locally administered (случайные MAC телефонов, часов и т.п.);
- повторы одной и той же точки чаще раза в 30 с, если вы стоите на месте.

Используется только GPS-провайдер: «сетевая» геолокация Android сама считается по Wi‑Fi, и база получилась бы замкнутой на саму себя.

## Ограничения Android

- **Частота Wi‑Fi-сканов.** С Android 9 система разрешает примерно 4 скана за 2 минуты. Для плотной записи отключите «Регулировка поиска Wi‑Fi» в Параметрах разработчика. Без этого при быстрой езде будут пропуски.
- **iOS** сбор не поддерживает (нет API сканирования Wi‑Fi), только Android.
- **BLE с выключенным экраном.** Android отдаёт только отфильтрованные результаты. В режиме «только маяки» это учтено (аппаратные фильтры), в режиме «все устройства» запись с выключенным экраном работать не будет.
- Приложение держит partial wake lock во время записи, это заметно расходует батарею.

## Приватность

Координаты, привязанные к MAC-адресам личных устройств людей, это персональные данные (в ЕС по GDPR). Стационарные точки доступа и маяки обычно не проблема, а запись обычных BLE-устройств рядом фактически отслеживает людей. Поэтому она выключена по умолчанию, а имена BLE-устройств не сохраняются вообще. База лежит на телефоне (`allowBackup=false`), наружу уходит лишь то, что вы сами экспортируете или отправляете на указанный вами сервер (только по HTTPS). Токен сервера хранится в настройках приложения в открытом виде, как и любые SharedPreferences; на устройстве без root он недоступен другим приложениям.

## Формат CSV

```
WigleWifi-1.4,appRelease=1.0,model=...,release=...,device=...,display=...,board=...,brand=...
MAC,SSID,AuthMode,FirstSeen,Channel,RSSI,CurrentLatitude,CurrentLongitude,AltitudeMeters,AccuracyMeters,Type
aa:bb:cc:dd:ee:ff,MyNet,[WPA2-PSK-CCMP][ESS],2026-10-06 14:03:11,6,-67,40.6401234,22.9444321,32.0,6.0,WIFI
11:22:33:44:55:66,ibeacon:<uuid>:1:2,Misc,2026-10-06 14:03:15,0,-71,40.6401300,22.9444400,32.0,6.0,BLE
```

Одна строка = одно наблюдение. Позицию самой точки получают вторым шагом: взвешенный центроид по наблюдениям (вес ≈ 10^(RSSI/10)), с отсевом подвижных точек по разбросу координат.
