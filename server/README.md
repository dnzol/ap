# AP Mapper server

Хранилище для данных из приложения: принимает CSV, хранит наблюдения в SQLite, считает позиции точек доступа и маяков и определяет местоположение по списку видимых сетей.

## Запуск (Docker)

```bash
cd server
cp .env.example .env
# впишите в .env длинный случайный токен:  openssl rand -hex 32
docker compose up -d --build
curl http://127.0.0.1:8000/healthz        # {"ok":true}
```

База лежит в `server/data/ap.db`. Бэкап — просто копия этого файла (лучше при остановленном контейнере или через `sqlite3 ap.db ".backup copy.db"`).

Без Docker: `pip install -r requirements.txt && API_TOKEN=... DB_PATH=./ap.db uvicorn app:app --port 8000`. Запускайте один процесс (`--workers 1`): запись в SQLite сериализуется внутри приложения.

## HTTPS (обязательно для приложения)

Приложение отправляет данные только на `https://` и требует действующий сертификат. Самый простой путь — Caddy на том же сервере, он сам получит сертификат Let's Encrypt:

```
maps.example.com {
    reverse_proxy 127.0.0.1:8000
}
```

В приложении укажите `https://maps.example.com` и токен из `.env`. Порт 8000 в `docker-compose.yml` привязан к 127.0.0.1, наружу напрямую он не торчит.

## API

Везде, кроме `/healthz`, нужен заголовок `Authorization: Bearer <API_TOKEN>`.

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/upload` | Тело — CSV формата WigleWifi-1.4. Ответ: `{"upload_id", "rows", "new", "skipped"}` |
| POST | `/locate` | Определить положение по скану (см. ниже) |
| GET | `/stats` | Счётчики: наблюдения, точки, маяки, загрузки |
| GET | `/aps.csv` | Вычисленные позиции точек. `?only_static=false` — вместе с подвижными |
| GET | `/gateway/accuracy` | Реальная точность Wi‑Fi-позиции по сравнению с GPS трекеров (см. раздел про шлюз) |
| GET | `/healthz` | Проверка живости, без токена |

Определение положения:

```bash
curl -s https://maps.example.com/locate \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"scan":[{"id":"aa:bb:cc:dd:ee:ff","rssi":-52},{"id":"11:22:33:44:55:66","rssi":-71}]}'
# {"lat":40.64,"lon":22.944,"accuracy_m":45.8,"used":2,"scanned":2}
```

Ответ 404, если ни одна сеть из скана не известна (или все известные подвижные).

## Как это считается

- **Дубликаты.** Наблюдение уникально по (тип, id точки, время, координаты), поэтому повторная отправка того же файла ничего не добавляет.
- **Позиция точки** — центроид координат всех наблюдений с весом `10^((RSSI − max RSSI)/10)`: ближе к местам, где сигнал был сильнее.
- **Подвижные точки.** Если наблюдения одной точки разбросаны дальше 400 м (для маяков 150 м), она помечается `is_static=0` и не участвует в `/locate` (мобильные хотспоты, Wi‑Fi в транспорте).
- **Locate.** Берутся до 6 самых сильных известных точек (минимум `MIN_OBS` наблюдений у каждой), вес `1/d²` при показателе затухания 3. Погрешность — разброс использованных точек вокруг результата, не меньше 15 м (для одной точки — не меньше 50 м). Это оценка, а не гарантия.
- Расчёт плоский: области, пересекающие линию перемены дат (±180°), не поддерживаются.

## Что сервер отбрасывает

Строки с неверным MAC, координатой (0,0) или вне диапазона, RSSI вне −127…0, погрешностью GPS хуже `MAX_ACC_M` (по умолчанию 100 м), сети с SSID на `_nomap`, а также любые BLE-записи, кроме маяков iBeacon/Eddystone. Последнее сделано намеренно: сервер не должен копить привязанные к координатам адреса личных устройств людей. Число отброшенных строк возвращается в `skipped`.

## Настройки (переменные окружения)

`API_TOKEN` (обязательно), `DB_PATH` (по умолчанию `/data/ap.db`), `MAX_UPLOAD_MB` (50), `MIN_OBS` (2), `MAX_ACC_M` (100).

## Тесты

```bash
pip install -r requirements.txt httpx pytest
pytest -q test_server.py
```

Тест гоняет полный цикл через HTTP: авторизацию, загрузку, идемпотентность, фильтры, `/locate`, `/aps.csv`.

Шлюз проверяется отдельно, без внешних библиотек: `python -m unittest test_gateway -v`. Тесты поднимают поддельную Аксенту и поддельный трекер по настоящему TCP.

# Шлюз для трекеров (подмена координат при valid_nav=0)

> **Важно:** текущий `gateway.py` разбирает текстовый протокол Wialon IPS. Навтелеком Smart работает по бинарному NTCB/FLEX, поэтому с ним шлюз в таком виде не заработает: нужен другой слой разбора пакетов. Логика подмены, обучения, сравнения с GPS, сглаживания и режимов (наблюдение, пилот) остаётся и переиспользуется. Разбор FLEX 3.0 пишется по реальным кадрам терминала, для этого сначала нужен перехватчик (раздел в конце).

```
Трекер → шлюз (порт 20332) → Аксента
            │
            ├─ valid_nav=1 → пакет уходит как есть; пары «сети + хороший GPS» пополняют таблицу точек,
            │                а Wi‑Fi-позиция сравнивается с GPS (точность видна в /gateway/accuracy)
            └─ valid_nav=0 + есть Wi‑Fi → координаты из таблицы подставляются в пакет
                                          (если сети известны), пакет уходит в Аксенту
```

Шлюз прозрачный: логин трекера и ответы Аксенты проходят насквозь, авторизацию делает сама Аксента. Любая ошибка разбора означает, что пакет уходит без изменений. Если Аксента недоступна, шлюз обрывает соединение с трекером, и трекер повторяет отправку сам.

## Что делает с подставленной точкой

- **Метка:** в параметры добавляются `nav_src:3:wifi`, `wifi_acc:2:<оценка точности, м>`, `wifi_n:1:<сколько точек использовано>`. По `nav_src` в Аксенте можно отличить такие точки от настоящего GPS.
- **Скорость и курс** считаются по предыдущей точке этого трекера (GPS или подставленной): расстояние / время и азимут. Wi‑Fi-оценка «дрожит» на десятки метров, поэтому смещение меньше max(30 м, оценка точности; не больше 150 м) считается стоянкой: координата не меняется, скорость 0, курс прежний. Скачок быстрее 150 км/ч считается выбросом, такой пакет не меняется.
- Скорость и курс по Wi‑Fi грубые: хорошо работают на стоянке и при медленном движении, на трассе точность низкая.

## Допущения, которые надо сверить с вашим трекером и Аксентой

Шлюз написан без образца пакета и без доступа к вашей Аксенте, поэтому на этих пунктах нужна проверка:

1. **Протокол Wialon IPS** (1.1 или 2.0), поля `#D#`/`#B#` по спецификации. Если трекер говорит на другом протоколе, разбор пакета нужно писать заново (остальная часть шлюза остаётся).
2. **valid_nav** лежит в поле params как `valid_nav:1:0`. Другое имя: `VALID_NAV_PARAM`.
3. **Wi‑Fi** лежит в параметрах с именем `wifi...` (`WIFI_PARAM_RE`), MAC-адрес и уровень сигнала рядом, например `wifi:3:aa:bb:cc:dd:ee:01=-61 aa:bb:...`. Разбор терпимый (MAC через `:`, `-` или без разделителей), но формат лучше подтвердить по реальному пакету.
4. **CRC16** для IPS 2.0: CRC-16/ARC по данным пакета вместе с последней `;`. Если CRC не сходится, пакет пересылается без изменений (счётчик `bad_crc` в логе). Значит, при неверном допущении подмена просто не включится, а не испортит данные.
5. **Аксента принимает подставленные координаты.** Возможно, ей нужен ненулевой `sats` (`SATS_OVERRIDE`) или `valid_nav=1` (`VALID_NAV_AFTER=1`). Это проверяется на пилоте.

## Включение по этапам

1. **Наблюдение.** В `.env` укажите `UPSTREAM_HOST`/`UPSTREAM_PORT` (адрес приёма трекеров в Аксенте), `SUBST_IMEIS` оставьте пустым. Запуск: `docker compose --profile gateway up -d --build`, открыть порт 20332/tcp. На одном-двух трекерах смените адрес сервера на адрес вашего VPS и порт 20332. Пакеты в Аксенту идут без изменений, а в логе (`docker compose logs -f gateway`) видно «подставил бы ...», база пополняется, копится сравнение с GPS.
2. **Пилот.** `SUBST_IMEIS=imei1,imei2`, `docker compose --profile gateway up -d`. У этих машин в Аксенте появляются подставленные точки с `nav_src=wifi`; сверьте на карте.
3. **Весь парк.** `SUBST_IMEIS=*` и смена адреса на остальных трекерах.

Откат на любом этапе: вернуть на трекерах прежний адрес Аксенты (или очистить `SUBST_IMEIS`).

## Как понять, что можно доверять

- `GET /gateway/accuracy` (с токеном) показывает `median_m`, `p90_m` и долю случаев, когда реальная ошибка была не больше заявленной точности. Данные набираются на пакетах с valid_nav=1: по текущей таблице считается Wi‑Fi-позиция и сравнивается с GPS, и лишь потом наблюдение пополняет таблицу.
- В логе раз в 5 минут печатаются счётчики: `substituted`, `shadow`, `nav0_no_wifi`, `nav0_no_match`, `nav0_outlier`, `learned_obs`, `bad_crc`, `errors`. Большой `nav0_no_match` означает, что таблица не покрывает эти места, а `nav0_no_wifi` означает, что трекер не присылает список сетей.

## Ограничения

- Таблица работает только там, где она заполнена. Шлюз пополняет её сам из пакетов с хорошим GPS (минимум 5 спутников, HDOP не больше 2,5, скорость не больше 40 км/ч), плюс можно загружать данные приложением.
- Порт шлюза принимает обычный TCP без шифрования, как и сама Аксента. Открывайте его только на нужном порту, а трекеры без валидного логина в Аксенте ничего не добьются.
- Обработка идёт в одном процессе; для парка в сотни машин этого достаточно. Если база сильно вырастет, пересчёт позиций точек стоит оптимизировать.

# Перехват трафика терминала Навтелеком (Flex)

`capture.py` пересылает трафик терминала в Аксенту **без изменений** и пишет кадры NTCB в hex (рукопожатие, согласование набора полей FLEX, пакеты `~A`/`~T`/`~E`) с проверкой контрольных сумм. По этому логу пишется разбор FLEX 3.0 для шлюза.

1. Нужен сервер с публичным IP и открытым портом 20332/tcp (тот же VPS, где будет всё остальное).
2. В `.env` задайте `UPSTREAM_HOST` и `UPSTREAM_PORT`: адрес и порт, на которые терминал сейчас шлёт данные в Аксенту.
3. Запустите: `docker compose --profile capture up -d --build`.
4. В конфигураторе терминала (один тестовый терминал) смените адрес сервера на адрес вашего VPS и порт 20332, протокол оставьте FLEX. Аксента продолжает получать данные как раньше, только через ретранслятор.
5. Дайте терминалу поработать 10-15 минут, лучше с несколькими событиями: стоянка, движение, по возможности место без GPS (подземная стоянка, гараж).
6. Заберите `data/capture.log` (по умолчанию записывается до 400 записей). В нём есть IMEI (кадр `*>S:...`) и координаты: замажьте их перед отправкой.
7. Верните на терминале прежний адрес Аксенты и остановите перехватчик: `docker compose --profile capture down`.

Если Аксента принимает терминалы на разных портах для разных протоколов, укажите порт именно для NTCB/FLEX.
